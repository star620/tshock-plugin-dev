# 13 GitHub 评论读取（封装 gh CLI）

目的：让 AI 能直接读取合作开发者在 GitHub 上留下的评论（issue 讨论 / PR 讨论 / Review 总结 / 代码行评论），无需用户手动复制粘贴。
**独立可用**：即使没有插件开发需求，也可以直接调用本能力做评论审核、查看、分析等通用工作。

## 1. 前置：安装并认证 gh

MCP 工具通过子进程调用本机 `gh`（GitHub CLI）。未安装时返回错误并提示安装。

```powershell
# 安装（Windows，二选一）
winget install --id GitHub.cli
# 或从 https://github.com/cli/cli/releases 下载解压后把 gh.exe 所在目录加进 PATH

# 认证（会用浏览器/粘贴 token）
gh auth login
# 或用已有的 GitHub PAT 直接认证
gh auth login --with-token < token.txt

# 验证
gh auth status        # 应显示 Logged in to github.com account <用户名>
```

认证方式：`gh` 使用其自身凭据（`gh auth login` 或 `GH_TOKEN` 环境变量），与 git 凭据相互独立。

## 2. MCP 工具调用对照

| 工具 | 参数 | 返回关键字段 |
|---|---|---|
| `read_github_comments` | `url` 或 `repo`+`number`；`comment_type`（all/description/conversation/review/code） | repo / number / kind(issue\|pr) / total / comments[type/author/body/path/line/state] |

**用法一：传 URL（自动解析是 issue 还是 PR）**

```
read_github_comments(url="https://github.com/owner/repo/pull/5")
read_github_comments(url="https://github.com/owner/repo/issues/3")
```

**用法二：传 repo + number（自动探测是 issue 还是 PR）**

```
read_github_comments(repo="owner/repo", number=5, comment_type="review")
```

**comment_type**：
- `all`（默认）：description + conversation + review + code 全部，按时间升序
- `description`：issue/PR 标题 + 正文 + 状态
- `conversation`：issue/PR 下的对话回复
- `review`：整体审查意见（state 可为 approved / changes_requested / commented）
- `code`：代码行评论（含 path / line / in_reply_to_id）

## 3. gh 命令速查（MCP 不可用时的兜底）

```powershell
# 看 PR 全部讨论（含 review 总结与行内评论摘要）
gh pr view <编号> --repo owner/repo --comments
# 看 issue 全部讨论
gh issue view <编号> --repo owner/repo --comments
# 结构化取各类评论（对应 MCP 内部实现）
gh api "repos/owner/repo/issues/<n>/comments" --paginate   # 对话评论
gh api "repos/owner/repo/pulls/<n>/reviews"  --paginate    # review 总结
gh api "repos/owner/repo/pulls/<n>/comments" --paginate    # 代码行评论
```

## 4. 常见错误

| 现象 | 原因 | 解决 |
|---|---|---|
| 未找到 gh / 安装提示 | gh 未安装或不在探测路径 | `winget install --id GitHub.cli`；或设 `GH_EXECUTABLE` 指向 gh.exe |
| 401 Bad credentials / 认证失败 | gh 未认证或 token 失效 | `gh auth login` 或设置 `GH_TOKEN`；`gh auth status` 检查 |
| 403 / rate limit | API 限流或权限不足 | 稍后重试；确认 token 有仓库读取权限 |
| 404 Not Found | 仓库名或编号错误；该编号不是 issue/PR | 核对 `owner/repo` 与编号；URL 里是 `/issues/` 还是 `/pull/` |
| 返回内容不是合法 JSON | gh 未认证等 | `gh auth status`；手动运行 `gh api ...` 看原始输出 |

## 5. 在插件开发流程中的接入

- **Phase 9 交付收尾**：若目标 PR / 仓库收到合作者 review comment 或 PR 未通过，先 `read_github_comments` 读取全部评论（review + code + conversation），再逐条分析处理，修复后重新走 Phase 6/7 验证。
- **日常协作**：用户给出任何 GitHub 评论页 URL 时，AI 可主动调用本工具读取并分析，无需用户粘贴内容。
