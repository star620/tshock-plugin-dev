# 10 排错手册

按症状定位，处理后重新走 Phase 6-7 验证。

## 编译类错误

### CS0117「不包含定义」/ CS1061「未包含成员」（类型存在但成员找不到）
- **原因（实测）**：该类型/成员定义在**未下载的子模块源码**里（如 `PacketTypes` 等 `TerrariaApi.Server` 类型定义在 TShock 的 `TerrariaServerAPI` 子模块 = `NyxStudios/TerrariaAPI-Server`，codeload zip 不含子模块）；或 API 在新版本已改名/移除（如 6.1.0 移除 `TShock.Utils.FindPlayer`、旧的 `MessageID` 改成了 `PacketTypes`）
- **处理**：读 `.gitmodules` 找子模块 → 下载对应源码 → grep 目标成员确认真实签名；或对照 `03-参考源码获取.md` 的「下载后立即 grep」

### CS0246「找不到类型/命名空间」（如 Terraria、TShockAPI）
- 原因：NuGet 包版本与代码不匹配，或 csproj 缺引用
- 处理：核对 `PackageReference TShock` 版本 = 目标 TShock 版本；TFM 正确

### CS0234「命名空间不存在」
- 原因：用了目标版本不存在的 API/命名空间
- 处理：对照 L1/L3 参考源核实签名，换公开 API

### 警告 NU1701（包兼容性警告）
- 原因：TShock 包 TFM 与项目 TFM 不一致
- 处理：把项目 TFM 改为与包 `lib/` 目录一致的 TFM

### 还原失败「无法解析 TShock」
- 原因：网络无法访问 nuget.org
- 处理：配置镜像源（如 `nuget.cdn.azure.cn`）后 `dotnet restore`

## 运行时加载错误

### 插件加载异常：`FileNotFoundException: TShockAPI`（最常见，实测踩坑）
- **症状**：`Plugin "xxx" has thrown an exception during initialization`，内因 `Could not load file or assembly 'TShockAPI, Version=X'`；服务器日志显示 `Startup aborted`，TShock 横幅（`TShock X 正在运行`）不出现
- **根因（实测）**：TShock 6.x 把 TShock 自身也作为插件加载，**`ServerPlugins/TShockAPI.dll` 是必需的**。若该文件缺失（清理 ServerPlugins 时误删、或目录被清空过），任何插件引用 TShockAPI 都会加载失败
- **修复**：从 TShock 官方发布包复制 `ServerPlugins/TShockAPI.dll`（+ `TShockAPI.deps.json`）回服务器目录，重启
- **另一根因**：插件引用的 TShockAPI 版本与服务器内嵌版本不一致（如服务器是 dev 构建，TShockAPI 版本可能是 `5.9.9.0` 占位号）。核对方法见下文「核对服务器 TShockAPI 版本」

### 核对服务器 TShockAPI 版本
```powershell
# 看服务器 ServerPlugins 里 TShockAPI.dll 的程序集版本
[System.Reflection.AssemblyName]::GetAssemblyName("<服务器>\ServerPlugins\TShockAPI.dll").FullName
# 看 NuGet 包版本
[System.Reflection.AssemblyName]::GetAssemblyName("$env:USERPROFILE\.nuget\packages\tshock\<版本>\lib\net9.0\TShockAPI.dll").FullName
```
- 两者应一致（官方 6.1.0 都是 `6.1.0.0`）；不一致时以服务器为准重编插件

### 服务器启动即退出：`REST配置无效` / 端口 7878 被占用
- **症状**：TShock 初始化后立刻提示 `你可能已经有绑定到端口7878的REST服务` 并退出
- **根因**：上一个服务器实例未完全退出，REST 端口未释放
- **修复**：确认无残留进程（`Get-Process TShock.Server*`），等待几秒端口释放后重启

### 插件加载异常：`FileLoadException` / `BadImageFormatException`
- 原因：插件 TFM 与服务端运行框架不一致，或 DLL 损坏
- 处理：确认 TFM = 服务端框架；重新 Release 编译部署

### 插件加载异常：`MissingMethodException` / `TypeLoadException`
- 原因：用了比服务端 TShock 更新的 API
- 处理：对照服务端实际 TShock 版本核实 API，降级写法

### 插件加载异常：`TypeInitializationException`（静态构造失败）
- 原因：静态字段初始化抛异常（如路径不可写、配置文件损坏）
- 处理：检查 `Path.Combine(TShock.SavePath, ...)` 目录可写；配置 JSON 合法

### 插件未出现在加载日志
- 原因：DLL 未放入 `ServerPlugins/`，或文件名/程序集名不符
- 处理：确认复制路径；确认 `AssemblyName` 与文件名一致

### 服务器启动即崩溃
- 原因：世界文件损坏 / 端口被占 / 插件兼容性
- 处理：先移除 `ServerPlugins/` 全部插件裸启动，确认服务器本身正常；再逐个加回插件定位问题插件

## 功能行为类问题

### 命令不生效
- 检查：权限名是否正确分配给了当前用户组；命令名是否冲突（`Commands.ChatCommands` 查重）；是否注册在 Initialize 中
- `TShock` 默认命令与插件命令冲突时，插件注册需用不同的命令名

### 事件不触发
- 检查：事件是否在 `Initialize` 注册；条件过滤（`RealPlayer`/`IsLoggedIn`）是否误拦；是否在 Dispose 被误注销

### 配置不生效
- 检查：`reload` 后是否重新读取；配置文件路径与文件名是否正确；JSON 属性名与文件一致

### 定时逻辑不执行
- 检查：`GameUpdate` 每帧触发，Tick 累计逻辑是否正确；`Config.Enabled` 开关是否打开

## 服务器网络相关（TShock 特性）

### 客户端连不上 / 连接被拒
- TShock 对同 IP 有连接抑制与封禁机制：短时间高频连接可能触发静默拒绝
- 处理：降低测试频率，等待封禁解除（分钟级）；使用不同 IP 测试

### 端口占用
- `netstat -ano | findstr <端口>` 找占用进程，先停旧实例再启动

## 日志查看指引
- 控制台输出：`server_out.log`（stdout）
- 错误输出：`server_err.log`（stderr）
- TShock 自身日志：`tshock/ServerLog.txt`（旧版在 `ServerLog.txt`）

## 万能回退
1. 移除 `ServerPlugins` 内全部插件，裸启动确认服务器 OK
2. 加回插件复现问题 → 缩小到插件本身
3. 用最小复现（删到只剩报错路径的代码）二分定位
