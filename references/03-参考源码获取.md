# 03 参考源码获取（四层策略）

目的：让 AI 写代码前有充分的 API 行为依据。按优先级从高到低使用，已有则跳过下一层。

## L1 用户本地版本化源码夹（最权威）

用户可能提供形如 `<版本文件夹>/` 的目录，内含：

| 内容 | 说明 |
|---|---|
| TShock 源码（`TShock-general-devel` / `TShock.sln` 等） | 查 `TShockAPI` 各类的实现细节 |
| OTAPI 源码（`OTAPI/`，含 Terraria 反编译源码） | 查 Terraria 内部类型、Hook 触发点 |
| references 目录（TShockAPI 源码 / Terraria 源码 / TerrariaServerAPI） | 直接查类定义 |

**用法**：先读 `TShockAPI` 关键类（`TShock.cs`、`TSPlayer.cs`、`Commands.cs`、`Permissions.cs`、`GetDataHandlers.cs`），再按需求读 OTAPI 的 HookEvents。读时注意版本是否与目标版本匹配。

## L2 用户本地插件收集仓库

用户提供插件收集仓库路径（通常一个文件夹含多个插件子目录）。用法：

1. 按需求提取关键词（如「商店」「Boss」「组队」）
2. 搜索仓库内相似插件源码
3. 重点看：事件注册方式、命令注册方式、配置读写模式、权限分配
4. 参考其代码结构但不照搬（遵循 `05-代码组织规范.md`）

## L3 NuGet 包（编译引用基础，必需）

- 官方包名 `TShock`，版本 = 目标 TShock 版本
- csproj 中 `PackageReference` 引用即可，无需任何本地 DLL
- 包缓存路径 `~/.nuget/packages/tshock/<版本>/`，可读其中的 XML 文档与程序集反射获取 API 签名

## L4 自动下载（无本地源码时**默认执行**，下载前先征得用户同意）

| 资源 | 来源 | 用途 | 拉取方式 |
|---|---|---|---|
| TShock 官方发布 zip | GitHub Releases `Pryaxis/TShock`（win-x64 资产） | 测试服务器 + `ServerPlugins/TShockAPI.dll` 编译兜底 | 下载资产 zip 解压 |
| TShock 源码 | `Pryaxis/TShock` tag `v<版本>`（如 v6.1.0） | `TShockAPI/`、`TerrariaServerAPI/` 源码 → API 行为权威参考 | 下载 tag 的 codeload zip，仅提取所需目录 |
| **TerrariaServerAPI 源码** | `NyxStudios/TerrariaAPI-Server`（TShock 的 `.gitmodules` 子模块，版本与 TShock tag 对应） | **定义 `PacketTypes`、`TerrariaPlugin`、`ServerApi` 等 `TerrariaApi.Server` 类型**（无此源码时这些类型查不到） | 下载对应分支/commit 的 codeload zip |
| **OTAPI 源码** | `DeathCradle/Open-Terraria-API`（分支 `upcoming`，即 OTAPI 3.x；实测 `Pryaxis/OTAPI` 不存在） | Terraria 内部类型 + Hook 触发点（含 Terraria 反编译源码） | 下载分支/对应版本的 codeload zip |
| 社区插件库 | `UnrealMultiple/TShockPlugin` | 相似插件源码参考 | 下载 zip 或按需提取 |
| 用户补充的仓库/本地源码（Phase 0 已问） | 用户提供 | 同类实现/工具源码参考 | 按需稀疏拉取或直接读取 |

**子模块检查（重要，实测踩坑）**：
- codeload 下载的 TShock zip **不含 git 子模块**（如 `TerrariaServerAPI`）
- 解压后**先读 `.gitmodules`**，找出子模块仓库，按需单独下载——否则 `TerrariaApi.Server` 相关类型（`PacketTypes` 等）永远查不到

**下载后立即 grep（避免盲搜）**：
- 定位目标 API 定义：`grep "enum PacketTypes"` / `class ServerApi` 等，先找到定义文件再深入
- 编译报 `CS0117`（成员不存在）/ `CS1061`（方法不存在）时，优先怀疑「类型在未下载的子模块源码里」或「API 在新版本已改名」，用 grep 确认真实签名

**版本对应规则**：
- TShock 发布说明（GitHub Releases body）会写明所用 OTAPI 版本（如 6.1.0 → OTAPI 3.3.11）
- 若 TShock 发布说明未写明，读 TShock 源码 `OTAPI/` 相关引用或按 OTAPI 最新稳定版就近匹配

**拉取命令示例**（Windows PowerShell）：
```powershell
# TShock 源码（稀疏：只解压 TShockAPI 目录）
Invoke-WebRequest "https://codeload.github.com/Pryaxis/TShock/zip/refs/tags/v6.1.0" -OutFile "tshock-src.zip"
Expand-Archive "tshock-src.zip" -DestinationPath "参考源码"
# OTAPI 源码（版本以 TShock 发布说明为准，分支 upcoming）
Invoke-WebRequest "https://codeload.github.com/DeathCradle/Open-Terraria-API/zip/refs/heads/upcoming" -OutFile "otapi-src.zip"
Expand-Archive "otapi-src.zip" -DestinationPath "参考源码"
```

**优先级**：遇到 API 疑问时，读源码优先于猜/记忆——如 `TShockAPI.dll` 编译报错找不到成员，直接 grep 对应源码确认真实签名。

## 禁止事项
- 禁止仅凭记忆写 TShockAPI 代码而不核对签名——API 随版本变化
- 禁止把用户私有数据（路径/账号/IP）写入 skill 或交付文档
