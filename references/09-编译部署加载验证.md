# 09 编译部署与加载验证

## 一、编译（Phase 6）

```powershell
# 还原并构建（Release）
dotnet build -c Release {{插件名}}.csproj
# 若有测试项目，跑测试
dotnet test {{插件名}}.Tests.csproj
```

**通过标准**：`Build succeeded`，0 错误 0 警告；测试全绿。
有警告不放过——警告往往提示潜在 bug（空引用、未用变量等）。

产物：`bin/Release/{{TargetFramework}}/{{插件名}}.dll`

## 二、部署（Phase 7 步骤 1）

0. **前置检查（实测踩坑）**：TShock 6.x 把 TShock 自身作为插件加载，`ServerPlugins/` 里**必须存在 `TShockAPI.dll`**（官方发布包自带）。若缺失，先从官方发布包补齐再部署，否则任何插件都会报 `FileNotFoundException: TShockAPI`。
1. 确认目标服务器已停止（`Get-Process TShock.Server*` 检查；存在则先 `taskkill /F /IM TShock.Server.exe`，并等待端口释放）
2. 定位 `ServerPlugins` 目录：
   - 用户提供 > 在服务器目录下探测 `ServerPlugins/`
   - 不存在则创建 `ServerPlugins/`
3. 复制 DLL：
   ```powershell
   Copy-Item "bin\Release\{{TargetFramework}}\{{插件名}}.dll" "<服务器目录>\ServerPlugins\"
   ```
4. 若插件带配置/数据文件，可同时清掉旧插件数据目录（`tshock/{{插件名}}/`）以测试全新初始化（需用户同意）

## 三、重启与验证（Phase 7 步骤 2-3）

启动服务器（后台运行，输出重定向到日志）：

```powershell
cd "<服务器目录>"
Start-Process .\TShock.Server.exe -RedirectStandardOutput server_out.log -RedirectStandardError server_err.log
```

等待服务器就绪后检查：

1. **进程存活**：`Get-Process TShock.Server*` 存在，未崩溃
2. **加载日志**：在 `server_out.log` / `ServerLog.txt` 中搜插件名，应看到加载成功信息，**无异常堆栈、无 `Exception`**
3. **重载测试**：若插件挂载了 `ReloadEvent`，可在控制台执行 `reload` 命令（若可交互）确认重载不报错
4. **卸载测试**：停止服务器，日志中不应出现插件相关未处理异常

**通过标准**：
- 服务器从启动到就绪全程无崩溃
- 插件加载日志正常、无 `Exception`/`Error` 字样
- 服务器能正常进入运行状态（生成世界/加载世界完成）

## 四、失败处理（按错误类型回退）

| 失败现象 | 回退阶段 | 处理 |
|---|---|---|
| 编译错误/警告 | Phase 6 | 修到 0 错误 0 警告再部署 |
| 加载报 `FileNotFoundException`（缺 TShockAPI 等） | Phase 3 | 补全 `ServerPlugins/` 依赖后重部署 |
| 插件加载异常/服务器启动崩溃 | Phase 5 → 6 | 审查事件注册/资源释放/异常处理，重编译重部署 |
| 加载正常但行为与需求不符 | Phase 4 → 5 | 对照需求摘要改实现，补/改测试 |
| 依赖参考源结论存疑（API 签名不符） | Phase 2 | 回到参考源码核对 API，再继续 |

回退通用规则：
- 修复后**必须重新编译（Phase 6）+ 重启验证（Phase 7）**，再决定是否继续后续阶段
- 重启前必须再次 `taskkill` 旧进程，确保端口释放
- 反复失败 → 将完整日志贴给用户说明问题，不要盲目重试

## 五、注意事项

- 服务器端口冲突：确保没有其他实例占用（每次重启前 taskkill）
- TShock 对同 IP 有并发抑制/封禁机制，测试连接时避免短时间高频重复连接
- 验证结束后将服务器保持停止状态（除非用户要求继续运行），避免占资源
