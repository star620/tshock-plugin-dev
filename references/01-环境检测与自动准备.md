# 01 环境检测与自动准备

目标：让任何环境（包括零配置的电脑）都能编译并加载验证插件。

## 检测命令（按序执行）

| 检测项 | 命令 | 期望结果 |
|---|---|---|
| .NET SDK | `dotnet --version` | 输出版本号；报错或为空 → 未安装 |
| TShock 服务器目录 | 用户提供 / 查找 `ServerPlugins` 或 `TShock.Server.exe` | 找到则记录路径 |
| NuGet 源 | `dotnet nuget list source` | 含 `nuget.org` 即可（默认就有） |

## 自动准备流程（每步前先向用户说明并征得同意）

### A. 安装 .NET SDK（未安装时）
1. 说明：需要安装 .NET SDK <版本>（由 Phase 1 版本解析确定，如 9.x）
2. 自动执行（Windows）：
   - 优先用 winget：`winget install Microsoft.DotNet.SDK.9`
   - 失败则用官方安装脚本下载安装
3. 安装后重新 `dotnet --version` 确认

### B. 准备测试服务器（无本地服务器时）
1. 说明：将下载 TShock 官方发布包（完整可运行服务器，约 34MB）作为测试环境
2. 下载：从 GitHub Releases 获取 `win-x64` 资产 zip（URL 解析见 `02-版本解析与兼容性.md`）
3. 解压到用户项目内的测试目录（如 `<项目>/TestServer/`），并记录路径
4. 首次启动生成世界与配置：
   - 复制一个已有 `.wld` 世界文件到服务器目录（用户提供优先）
   - 否则用 `-autocreate <1-3>`（1 小 / 2 中 / 3 大）参数启动让服务器自动建世界
5. 确认服务器能正常启动后停止，留待 Phase 7 使用

### C. 还原 NuGet 包
- `dotnet restore` 会自动还原 `TShock` 官方包（缓存于 `~/.nuget/packages/tshock/`）
- 若公司/校园网络无法访问 nuget.org，提示用户配置国内镜像源（如 `https://nuget.cdn.azure.cn/v3/index.json`）

## 探测记录

将检测结果记录为「环境清单」，进入后续阶段时引用：

```
环境清单：
- .NET SDK：<版本> ✓/✗
- 测试服务器：<路径>（本地/自动下载）
- 目标 TShock 版本：<版本>
- 目标 TFM：<net9.0 等>
```

## 注意事项
- 探测与下载只做「必要」的部分：用户已有服务器就不下载，已有 SDK 就不安装
- 下载 zip 后校验文件名含正确平台（`win-x64`）与版本号，防止下错
- 服务器下载解压后若端口冲突，Phase 7 启动时先确认原服务器已停止
