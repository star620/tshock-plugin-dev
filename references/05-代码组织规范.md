# 05 代码组织规范

> 目标：分类封装、易维护。**一个类一个职责，每个类 ≤ 400 行；禁止所有方法堆在一个文件。** 代码用简单明了的语言写中文 `//` 注释。

## 分类结构（默认划分）

| 文件 | 职责 | 何时存在 |
|---|---|---|
| `Plugin.cs` | 插件信息、文件路径、Initialize/Dispose（事件注册/注销）、配置重载 | 必有 |
| `Commands.cs` | 所有聊天命令的注册与处理 | 有命令时 |
| `Configuration.cs` | 配置文件类的读取/写入/默认值 | 有配置时 |
| `CacheData.cs` | 高频变化数据的持久化（玩家数据等） | 有数据时 |
| `Utils.cs` | 通用工具方法（消息格式化、颜色等） | 有工具需求时 |
| `Core/` | 纯业务逻辑类（不碰 `Main.*`/`TShock.*` 运行时静态状态） | 逻辑复杂时可测时 |

## Plugin.cs 结构（#region 分区）

```
#region 插件信息        → PluginName / Author / Version / Description
#region 文件路径        → MainPath / 配置文件路径 / 缓存文件路径
#region 注册与释放      → 构造函数 + Initialize（注册全部事件）+ Dispose（成对注销）
#region 配置重载        → ReloadConfig（挂 GeneralHooks.ReloadEvent）/ LoadConfig
#region <事件名>事件    → 每个事件一个 region，如「玩家进服事件」「玩家离开服务器事件」
```

## 事件注册/释放必须成对

```csharp
public override void Initialize()
{
    ServerApi.Hooks.ServerLeave.Register(this, this.OnServerLeave); // 注册
}

protected override void Dispose(bool disposing)
{
    if (disposing)
        ServerApi.Hooks.ServerLeave.Deregister(this, this.OnServerLeave); // 注销
    base.Dispose(disposing);
}
```

## 配置文件规范

```csharp
internal class Configuration
{
    [JsonProperty("插件开关", Order = 0)]   // 中文可读名
    public bool Enabled { get; set; } = true; // 默认值

    public void Write() { /* JsonConvert 序列化写入 */ }
    public static Configuration Read() { /* 不存在则创建，存在则反序列化 */ }
}
```

- 配置路径：`Path.Combine(TShock.SavePath, 插件名, "配置文件.json")`
- 反序列化失败要给出友好报错（含行号/路径），不能让服务器崩溃

## 注释规范
- **一律用 `//` 中文单行注释**，解释「为什么」与「关键逻辑」，不写废话
- **禁止 `/// <summary>`、`<param>`、`<returns>` 等 XML 文档注释**——类、方法、属性、字段都用 `//`（行尾 `//` 或上一行 `//`），不写 `///` 三斜杠
- 每个 region 顶部一行 `//` 注释说明该区域用途
- 公共方法用 `//` 注释说明入参/返回/用途，不用 XML 标签

## 可测性要求
- 业务逻辑写成不依赖游戏运行时静态状态的纯类（依赖通过参数传入）
- 触碰 `TShock.Players`、`Main.*`、`TShock.Config` 的代码是「粘合层」，保持在事件/命令方法内，不做单测

## 审查时的红线
- ❌ 一个文件超 400 行且职责混杂 → 拆分
- ❌ 方法命名含糊（如 `do`、`handle`）→ 改动词开头
- ❌ 魔法数字无注释 → 常量或注释
- ❌ 事件注册了不注销 → 补齐
